# הסבר על המערכת

## הגדרת סביבה ראשונית

כדי להריץ את האפליקציה בפעם הראשונה, יש לבצע את השלבים הבאים:

1.  **התקנת שרת מקומי:** יש להתקין סביבת פיתוח מקומית הכוללת Apache, MySQL ו-PHP, כגון [XAMPP](https://www.apachefriends.org/index.html) או [WAMP](https://www.wampserver.com/en/).
2.  **הגדרת מסד הנתונים:**
    *   יש ליצור מסד נתונים חדש (למשל, דרך phpMyAdmin).
    *   יש לייבא את מבנה הטבלאות מקובץ ה-SQL של הפרויקט (בהנחה שקיים קובץ כזה). **הערה:** לא נמצא קובץ SQL בפרויקט, לכן יש ליצור את הטבלאות באופן ידני לפי מבנה הקוד.
    *   יש לעדכן את פרטי החיבור למסד הנתונים בקובץ `config/config.php` (שם משתמש, סיסמה, שם מסד הנתונים).
3.  **הרצת האפליקציה:** יש למקם את קבצי הפרויקט בתיקיית ה-`htdocs` (ב-XAMPP) או `www` (ב-WAMP) ולגשת לאפליקציה דרך הדפדפן.

## Backend (הצד הלוגי של השרת)
*   **שפה**: האפליקציה כתובה ב-PHP.
*   **מבנה**: הקוד מאורגן בצורה מודולרית. הקבצים החשובים נמצאים בתיקייה `core`:
    *   `init.php`: זהו הקובץ שמתחיל את כל האפליקציה. הוא טוען את כל ההגדרות והקבצים הנחוצים, מתחיל את ה-"session" (החיבור של המשתמש), ובודק הרשאות גישה לדפים השונים.
    *   `auth.php`: זהו המוח של האבטחה. הוא אחראי על כל מה שקשור לאימות משתמשים: התחברות, הצפנת סיסמאות, יצירת טוקנים לאבטחה (כמו CSRF), אימות אימיילים ואיפוס סיסמה.
    *   `user.php`: קובץ זה מנהל את כל הפעולות שקשורות למשתמשים, כמו רישום משתמש חדש, עדכון פרטים, קבלת רשימת משתמשים לפי תפקיד, וכו'.
    *   `db.php`: קובץ זה מנהל את החיבור למסד הנתונים ומספק דרך נוחה לשלוף ולהכניס נתונים.
*   **נקודת כניסה**: הקובץ `index.php` הוא הדף הראשון שנטען. הוא בודק אם המשתמש מחובר, ואם לא - מפנה אותו לדף ההתחברות (`pages/login.php`).

## Docker
בקבצים שנסקרו, **לא נמצאו קבצי הגדרות של Docker**. זה אומר שככל הנראה הפרויקט כרגע לא מוגדר לרוץ בסביבת Docker, אלא מותקן ישירות על שרת ווב.

## בדיקות ואבטחת קוד

אבטחת קוד היא תהליך מתמשך. הנה מספר המלצות וכלים לבדיקה וחיזוק האבטחה של האפליקציה:

### בדיקות אבטחה סטטיות (SAST - Static Application Security Testing)
כלים אלו סורקים את קוד המקור של האפליקציה (מבלי להריץ אותו) ומחפשים חולשות אבטחה ידועות, כגון הזרקות SQL, XSS, ובעיות לוגיות. זהו "קומפיילר האבטחה" ששאלת עליו.
*   **כלים מומלצים:**
    *   [SonarCloud](https://sonarcloud.io/) / [SonarQube](https://www.sonarqube.org/) (יש גרסאות חינמיות)
    *   [Snyk Code](https://snyk.io/product/snyk-code/)
    *   [Psalm](https://psalm.dev/) (מתמקד במציאת שגיאות בקוד PHP, אך יכול למצוא גם בעיות אבטחה)

### בדיקת תלויות (Software Composition Analysis - SCA)
הפרויקט משתמש בספריות קוד חיצוניות המנוהלות על ידי `Composer` (נמצאות בתיקיית `vendor`). חשוב לוודא שספריות אלו אינן מכילות חולשות אבטחה ידועות.
*   **כלים מומלצים:**
    *   **Composer Audit:** ניתן להריץ את הפקודה `composer audit` בטרמינל כדי לקבל רשימה של תלויות עם חולשות ידועות.
    *   [Snyk Open Source](https://snyk.io/product/open-source-security-management/)
    *   [Dependabot](https://github.com/dependabot) (משולב ב-GitHub)

### עקרונות אבטחה נוספים
*   **עדכניות:** יש לשמור על גרסת ה-PHP וכל הספריות (dependencies) עדכניות. עדכונים כוללים לעיתים קרובות תיקוני אבטחה חשובים.
*   **הגדרות שרת:** חשוב להגדיר את השרת בצורה מאובטחת. לדוגמה, למנוע גישה ישירה לקבצים רגישים (כמו `config.php`) ולהגדיר הרשאות קבצים נכונות.
*   **סביבת ייצור (Production):** יש לוודא שבסביבת הייצור, הצגת שגיאות PHP מפורטות (error reporting) כבויה, כדי לא לחשוף מידע רגיש לתוקפים.

## אבטחה מובנית באפליקציה
המערכת מיישמת מספר מנגנוני אבטחה חשובים:
*   **הצפנת סיסמאות**: סיסמאות לא נשמרות כטקסט רגיל, אלא מוצפנות באמצעות אלגוריתם חזק ומודרני (`BCRYPT`).
*   **סשנים מאובטחים (Secure Sessions)**: המערכת דואגת שהתקשורת של המשתמש המחובר תהיה מאובטחת.
*   **הגנה מ-CSRF (Cross-Site Request Forgery)**: המערכת משתמשת בטוקנים כדי לוודא שפעולות רגישות מבוצעות רק על ידי המשתמש עצמו.
*   **אימות אימייל**: משתמשים חדשים חייבים לאמת את כתובת האימייל שלהם.
*   **בקרת גישה מבוססת תפקידים (RBAC)**: המערכת בודקת את תפקיד המשתמש ונותנת לו לגשת רק לדפים המורשים לו.
